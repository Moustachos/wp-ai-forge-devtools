## Calibration

**Iteration 1.** First replay (plugin `82c65d9`): 80 generations changed,
0 templates, idempotent, no block-level regression, but **33 valid generations
changed**. Every change on a valid document fell in one of these:

| change | valid documents changed | invalid documents it repaired |
|---|---|---|
| paragraph margin, JSON only, written inline | 14 | 0 |
| heading margin, JSON only, written inline | 14 | 0 (4056 stayed invalid) |
| group margin, JSON only, written inline | 1 (4242) | 1 (5866) |
| paragraph colour, JSON only or conflicting, written inline | 2 (7009, 5932) | 0 (7024, 1862 stayed invalid) |
| paragraph preset classes added | 4 (1269, 2987, 4121, 6698) | 0 |
| quote preset font-size class added | 1 (1869) | 0 |

Probing the lab editor showed why: `getSaveContent()` does emit these
(`<p style="margin-top:…">`, `has-text-color`, `has-small-font-size`), yet
`parse()` marks the shorter markup valid. A deprecated `save()` with narrower
supports accepts it and the editor migrates the block on open. So a JSON-only
value of these properties is never what makes such a block invalid, and writing
it can only change a valid document. The same deprecations do not accept an
HTML-only value, and a group whose other attributes a deprecation does not know
(5866 has a border) is still rejected.

The table was right about what `save()` emits and wrong as a proxy for what the
editor rejects. Removing margin from the group row would also have dropped the
margin lift that repairs 5815 (margin misplaced at the style root), so the
calibration is narrower than removing rows:

- paragraph margin and colour, heading margin, group margin: still lifted from
  the markup into the JSON, never written from the JSON into the markup;
- paragraph and quote: no class is added.

Plugin commit `5b3c9e3` "Keep the block validity repair off what deprecated
saves accept", with the corpus shapes pinned as byte-identity cases and two
tests that the group margin lift and the quote margin write still happen.

**Iteration 2.** All three properties hold (results above). The only repair
the calibration cost is 5866 (pre-August, gemini-3-flash-preview, group
margin beside a border), which stays invalid.

**Parked question (malformed tokens on both sides).** No valid generation and
no template in the corpus carries `var:preset|x|x|…`, `var(--wp--preset|` or
`#transparent` anywhere. The only carriers are five invalid generations (6313,
6489, 6506, 6823, 7552), all repaired to valid. The one-sided token repair
needs no guard on this evidence.
